# Spark iOS

This repository contains the Spark iOS design system (theming, common code, components, resources and demo app) for SwiftUI and UIKit, as a single Swift package.

See [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) for the detailed architecture and [`docs/CLAUDE_SKILLS.md`](docs/CLAUDE_SKILLS.md) for all the skills.

# Context

| Path | Description |
|---|---|
| `Modules/Theming` | Theming code (`SparkTheming`): `Theme`, tokens (colors, spacings, ...), `ComponentToken`. |
| `Modules/Common` | Common code used by all components (`SparkCommon`). Some code is protected by `@_spi(SI_SPI)`. |
| `Modules/Components/XXX` | One package per component (`SparkComponentXXX`). |
| `Resources` | The Spark iconography (`SparkResources`). |
| `Spark` | The umbrella target exporting every module (`Spark/Sources/Core/Import.swift`). |
| `Demo` | The demo app implementing the theming and the components. |

# Components Architecture

> **New components are developed for SwiftUI only.** They have no **UseCase**, **Model** and **ViewModel**: the styling rules live in the **Token** (exposed through `theme.component.xxx`) and are applied by the views through private **ViewModifiers**.
> The UseCase / Model / ViewModel folders remain only in the **legacy** components which still have a UIKit view (`SparkUIXXX`). **Never remove a ViewModel, UseCase or Model still used by the UIKit view.**
> Reference implementation: `Modules/Components/InputOTP`.

- Sources:
  - Core: productive code.
    - AccessibilityIdentifier: only public accessibility identifier keys in an enum, used by the views.
    - Constants: constants used by the views (and the use cases for legacy components).
    - Documentation.docc: the DocC documentation, with image resources generated by the snapshot tests.
    - Enum: the enums used to configure the component.
    - Environment: the `EnvironmentValues` used by the SwiftUI component (not by UIKit).
    - Extension:
      - Token: `ComponentToken+XXX` (public `theme.component.xxx`) and `EnvironmentTheme+XXXToken` (internal shortcuts `self.theme.colors`, ...).
      - Others (`Enum`, `Foundation`, `SwiftUI`, ...): internal extensions holding the non-styling rules (formatting, validation, ...).
    - Token: the token values (colors, spacings, sizes, ...) consumed by the views, grouped by category and derived from the theme. State-dependent values are public methods.
    - View: the SwiftUI views (`SparkXXX`), and the UIKit views (`SparkUIXXX`) for legacy components.
    - ViewModifier: private view modifiers reading the tokens from `@Environment(\.theme)`, with an internal `View` extension.
    - Model *(legacy)*: the models set by the use cases and consumed by the views.
    - UseCase *(legacy)*: the rules of the component.
    - ViewModel *(legacy)*: the view model consumed by the views, with no business rules. It only calls use cases and sets observable properties.
  - Testing: protected public code used for the tests. Generally only `Sourcery.generated.swift`.

- Tests:
  - SnapshotTests: the snapshot tests.
  - UnitTests: the unit tests. Must have the same nomenclature as the productive code (`Sources/Core/Enum/Intent.swift` -> `Tests/UnitTests/Enum/IntentTests.swift`).

## Creation order

- **New component (SwiftUI only)**:
  1. Enum
  2. Token (+ `ComponentToken+XXX`, `EnvironmentTheme+XXXToken`)
  3. Environment
  4. ViewModifier
  5. View
  6. Tests
  7. Documentation
- **Legacy component (with UIKit)**:
  1. Enum
  2. Model
  3. Token
  4. Environment
  5. UseCase
  6. ViewModel
  7. View
  8. Tests
  9. Documentation

# Best practices

- Add unit tests if not present.
- Add Marks to separate the code:
  - `// MARK: - Properties`
  - `// MARK: - Public Properties`
  - `// MARK: - Private Properties`
  - `// MARK: - Initialization`
  - `// MARK: - Methods`
  - `// MARK: - Tests`
  - `// MARK: - Type Alias`
  - `// MARK: - View`
  - `// MARK: - Setup`
  - `// MARK: - Getter`
  - `// MARK: - Setter`
  - `// MARK: - Equatable`

- In a *switch*, if there is one return for each case, use a single return directly on the *switch*:

```swift
// Do:
func test() -> String {
  return switch intent {
    case .main: "Main"
    case .other: "Other"
  }
}

// Don't do:
func test() -> String {
  switch intent {
    case .main: return "Main"
    case .other: return "Other"
  }
}
```

# Rules

- Some public code is protected by an `@_spi(SI_SPI)` to not be available for the consumers of the design system. In productive or tests code, add `@_spi(SI_SPI)` when it is needed.
- File headers: `Created by {Firstname Lastname} on DD/MM/YYYY`. The copyright year is the current year for new files only; keep the year of the existing files.
- Tests:
  - Run sourcery before creating tests.
  - Use **Swift Testing** as much as possible. Exceptions still using **XCTest** (legacy components only):
    - The ViewModel tests.
    - The UseCase tests when the use case contains other use cases.
- Do not update the Deprecated files (`XXXDeprecated.swift`) or the files in a Deprecated folder (`ViewModel/Deprecated/MyViewModel.swift`), except when asked to deprecate some code.

# Commands

Run from the package folder (e.g. `cd Modules/Components/Button`), or use the `Makefile` from the repository root (see [`docs/MAKEFILE.md`](docs/MAKEFILE.md)).

- Sourcery: `sourcery` (or `make sourcery`)
- Swiftlint: `swiftlint`
- Build: `make build`
- Tests: `make test`
- DocC: `make docc`
- Clear the snapshots: `make clear-snapshots`
